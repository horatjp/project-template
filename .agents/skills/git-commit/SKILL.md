# git-commit — このプロジェクトのコミット規約

変更を関心単位のコミットに分け、下の形式でメッセージを書いてコミットする。

## 規約

- **形式**: `<gitmoji> <type>(<scope>): <subject>`(scope は任意)。本文は「なぜ」を書く
- **言語・文体**: `git log --oneline -10` の既存メッセージに合わせる(履歴が無ければ README の言語)
- **分割**: 独立してリバートできる関心単位(依存 / 設定 / コード / テスト / 文書)。
  バグ修正とリファクタリング、機能追加と整形は別コミット。各コミット後もビルド・テストが通る状態を保つ
- **取り込む範囲**: 自分の作業の変更だけ。ユーザーの未コミット変更を一括で `git add .` しない

## 1ファイル内の変更を分けてコミットする

対話的な `git add -p` は使えないので、パッチを編集して部分ステージする:

```bash
patch=$(mktemp "${TMPDIR:-/tmp}/split.XXXXXX")
git diff -U1 -- <file> > "$patch"   # 文脈行を減らすと近接した変更がハンクに分かれやすい
# パッチから、今回コミットしないハンク(@@ 行から次の @@ 行の手前まで)を丸ごと削除する。@@ 行の数値は書き換えない
git apply --cached "$patch" && git diff --cached
```

## Gitmoji(最頻出)

| Gitmoji | Type | 用途 |
|---|---|---|
| ✨ | feat | 新機能 |
| 🐛 | fix | バグ修正(🚑 緊急 / 🔒️ セキュリティ) |
| ♻️ | refactor | リファクタリング |
| ⚡️ | perf | 性能改善 |
| 🎨 | style | コード構造・整形 |
| 📝 | docs | 文書 |
| ✅ | test | テスト |
| 🔥 | - | コード・ファイルの削除 |

依存関係・UI/UX・設定/CI などは同ディレクトリの `gitmoji-reference.md` を参照する。

## プロジェクトへの適応

このファイルは雛形。プロジェクトに既存のコミット規約(Gitmoji を使わない・言語固定・scope 必須など)が
あれば、規約と表を書き換えて合わせる。コミットの取り消し(`git reset` 等)が権限で拒否されたら、
ユーザーに `! git reset --soft HEAD~1` などの実行を依頼する。
