# session-end — セッション終了処理

セッションをまたぐ情報伝達はファイルのみ。会話にしか無い情報を残さず終えることが目的。

## 手順

1. **未コミットの確認** — 作業したリポジトリ(ワークスペース自体が git ならそれも含む)で
   `git status` を確認する。未コミットの変更があれば関心単位のコミットにまとめて提案し、
   承認されたら実行する(節目を未コミットのまま持ち越さない。プッシュは提案まで)
2. **書き漏れチェック** — この会話で決めたこと・調べたこと・失敗の学びのうち、まだ
   ファイルに無いものを洗い出し、該当先へ書き込む — ワークスペースなら `docs/decisions/`・
   `docs/` の生きた文書・`materials/`、リポジトリなら `docs/decisions/`・`docs/knowledge/`・
   `docs/learnings.md`(層の境界はワークスペース AGENTS.md「記録の境界」)
3. **journal 反映**(ワークスペース配下のみ)— 今日の `journal/YYYY-MM-DD.md` に本日の
   出来事・節目が反映されているか確認し、足りなければ追記する
   (日付は環境の現在日付を確認して書く)
4. **STATUS 更新** — ワークスペースの `STATUS.md`(および作業したリポジトリの
   `docs/STATUS.md`)を「今」に更新し、**次の一手**を明記する
5. **報告** — 更新したファイルと次の一手を1画面に収めて報告し、締める

multi-agent モジュールで並列運用中の builder は手順 2・4 を行わない: 現在地・次の一手・
検証結果・ブロッカー・記録すべき判断を担当 Issue(または PR)に書いて scribe へ引き継ぐ
(共有文書への反映は scribe の担当。AGENTS.md「並列運用」節の記録の分担)。

## 原則

- 「後で書く」で終えない。このスキルの完了 = 全項目がファイルに反映済み
  (並列運用中の builder は担当 Issue/PR への記録と scribe への引き継ぎで完了。
  共有文書への反映は scribe が行い、change 完了の条件になる)
