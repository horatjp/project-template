# docs/ — 生きた文書と決定記録

主題別の「生きた文書」を置く(事業側の要件 `requirements.md`・関係者情報など)。

- 生きた文書は**現在形**を保つ — 内容が変わったら上書き更新する(履歴は git に任せる)。
  frontmatter は不要
- `decisions/` だけは別ルール: 事業・運営判断の決定記録を OKF 互換 frontmatter で
  1件1ファイルで追記していく(書式は `decisions/_template.md`)。
  **「今どうなっているか」は生きた文書、「なぜそうしたか」は decisions**
- `learnings.md` はワークスペース運営で AI が失敗したときの学び(ゲート・書式・昇格先は冒頭のコメント)。
  コードや技術の学びは各リポジトリの `docs/learnings.md` へ
- 技術的な文書・決定は各リポジトリ(`repos/` 配下)の `docs/` へ。
  ここに置くのは事業・運営側とリポジトリ横断のものだけ
