4. **P3: 根拠の強さ・設計の記述を修正する。** proposal.md:27,44-45,62。
   AIがチェックを書けることは事実だが「ゲートの保証がゼロ」は広すぎる。未チェックの design/tasks と、同一パッチ内の proposal 更新との併用は拒否している。「承認の出所を保証しない」が正確。形式検証も公理への入力の真正性までは与えないため、記事の証明検査とチェックの出所確認を同一視しない。

## 2の事実確認・代案

- **静的には主張どおりの経路がある。** proposal 自体は対象外(scripts/check-proposal-approved.sh:100-105)。別操作で記入後、既存ファイルの `[xX] ユーザー承認` に一致すれば通る(:117-125)。両層のスクリプトは `cmp` で一致した。同一パッチ内の proposal と design/tasks は拒否する(:109-114)ため、そこは区別する。実発火による再現は未実施。

## ask の確認結果

### Codex

- ローカルは `codex-cli 0.166.0`。npm 配布物には JS 起動ラッパー・ネイティブバイナリ等があり、調査した配布先には hooks の Rust ソースは無かった。help は承認方針 `on-request` / `never`、自動審査の `--approve-for-me`、全確認を飛ばす bypass オプションを示すが、hook ask の対応は説明していない。
- ctx7 `/openai/codex` の [output_parser.rs](https://github.com/openai/codex/blob/main/codex-rs/hooks/src/engine/output_parser.rs) 抜粋は Ask を unsupported と判定する。さらに [pre_tool_use.rs](https://github.com/openai/codex/blob/main/codex-rs/hooks/src/events/pre_tool_use.rs) の `parse_completed` は invalid_reason を Failed として記録するだけで should_block を立てない。他の hook が拒否しない限り、この ask 自体による停止はないという**ソース読解**。
- ローカルの `.../@openai/codex/node_modules/@openai/codex-darwin-arm64/vendor/aarch64-apple-darwin/bin/codex` にも `PreToolUse hook returned unsupported permissionDecision:ask` の文字列を確認した。**文字列の存在は実行経路の実証ではない**。ctx7 の参照先は main で、0.166.0 の固定コミットに対応するとまでは確認できていない。
- 従って「denyだけテストされている」より強い不採用根拠がある。少なくとも現時点で両CLI共通 ask を前提に実装しない。ローカル実機での最終挙動・各権限モードは**要確認**。

### Claude Code

- ctx7 の公式 [hooks-guide](https://code.claude.com/docs/en/hooks-guide) と [hooks reference](https://code.claude.com/docs/en/hooks) は、構造化制御を stdout JSON + exit 0 とし、PreToolUse の hookSpecificOutput に permissionDecision を置く。形は以下。stderr JSON + exit 2 は ask の形ではない。

  ```json
  {"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecision":"ask","permissionDecisionReason":"対象の提案全体への承認を確認してください"}}
  ```

- 同リファレンスの auto mode の説明では、hook ask は通常人間の確認へ進む。保護パス等では classifier が先に拒否する例外があり、すべてのツールで必ず人間に届くとは言えない。
- [settings-reference](https://code.claude.com/docs/en/settings-reference) は **permissions.ask ルール**なら bypassPermissions でも確認、dontAsk なら拒否と説明している。ただし今回得た資料だけでその記述を **hook ask** に一般化しない。hook ask の bypass/dontAsk とローカル版での挙動は**要確認**(実発火なし)。deny は全権限モードで停止すると hooks-guide に明記されている。
